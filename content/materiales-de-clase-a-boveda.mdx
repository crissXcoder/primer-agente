# De tus documentos de clase a tu bóveda de Obsidian

Esta guía reúne documentos de un curso en una carpeta de la bóveda para que puedas buscarlos, enlazarlos y estudiarlos. La conversión crea copias en Markdown; tus originales se quedan en su carpeta.

> [!note] Antes de empezar
> Si todavía no has instalado MarkItDown, primero sigue la guía [MarkItDown: convierte tus documentos a Markdown](/guias/markitdown-convertir-documentos). Aquí nos enfocamos en pasar un conjunto de materiales de clase a tu bóveda.

<Callout type="peligro" title="Datos y privacidad">
  Conserva tus documentos originales en tu equipo y haz una copia de respaldo antes de convertir. Las listas de estudiantes, calificaciones, datos personales y materiales de terceros no deben subirse a un repositorio público ni enviarse a servicios externos sin permiso. Respeta los derechos de autor y usa los materiales de docentes para tu estudio personal salvo que tengas autorización para otros usos. Aunque la bóveda y los archivos convertidos estén en local, lo que un agente lea se envía al proveedor del modelo. No le pidas leer material confidencial ni información personal de otras personas.
</Callout>

## Elige carpetas separadas

1. Deja los archivos originales en su carpeta de origen; no los muevas ni edites durante este proceso.
2. Copia esa carpeta como respaldo en otra ubicación.
3. Dentro de la bóveda, prepara una carpeta para los resultados, por ejemplo `Materiales/Historia del arte/`. La guía de Obsidian explica cómo abrir la carpeta de tu bóveda si todavía no tienes una.
4. No uses la carpeta de origen como destino. El script rechaza destinos que estén dentro del origen para reducir el riesgo de recorrer después los Markdown que acaba de crear.

Una ruta es la dirección de una carpeta en tu equipo. Si contiene espacios, ponla entre comillas en los comandos. Por ejemplo, `"C:\Users\Ana\Clases\Historia"` o `"/Users/ana/Clases/Historia"`.

## Prueba MarkItDown con un archivo

MarkItDown puede convertir varios formatos a Markdown. Su CLI permite indicar un archivo y una ruta de salida. El resultado puede perder parte del diseño original: revisa tablas, fórmulas, imágenes y saltos de página antes de confiar en la conversión.

Si MarkItDown ya está instalado en el entorno de Python que tienes activo, abre una terminal y ejecuta lo siguiente, cambiando ambas rutas por las tuyas:

```sh
markitdown "RUTA-ORIGEN/una-lectura.pdf" -o "RUTA-BOVEDA/Materiales/Curso/prueba.md"
```

En Windows usa la misma sintaxis con rutas de Windows, por ejemplo `"C:\\Users\\Ana\\Clases\\una-lectura.pdf"`. La opción `-o` señala el archivo de salida. Abre `prueba.md` y compara títulos, tablas y contenido con el original antes de convertir un lote.

<Callout type="tip" title="Ejecutar con uv sin activar un entorno">
  La documentación de uv permite pedir dependencias para una sola ejecución. Si tienes uv instalado, esta forma descarga/prepara MarkItDown para el comando y no requiere activar primero un entorno virtual. Se necesita conexión para obtener paquetes; uv puede conservarlos en su caché. No uses esta opción para material confidencial si tu configuración instala paquetes desde una fuente que no autorizaste.
</Callout>

```sh
uv run --no-project --with "markitdown[all]" -- markitdown "RUTA-ORIGEN/una-lectura.pdf" -o "RUTA-BOVEDA/Materiales/Curso/prueba.md"
```

`[all]` pide las dependencias opcionales que el proyecto publica para distintos formatos. Si ya tienes un entorno aislado, puedes seguir las guías de [Python](/guias/instalar-python) y [uv](/guias/instalar-uv) para trabajar dentro de él. La documentación de Python describe `venv` como un entorno independiente para paquetes.

## Simula el lote

Descarga [`convertir_a_boveda.py`](/descargas/convertir_a_boveda.py) en tu computadora. El script completo también está al final de esta guía. Colócalo donde puedas localizarlo desde la terminal.

Antes de la conversión real, corre una simulación con el comando siguiente. Sustituye las rutas y etiqueta. No pongas la carpeta de destino dentro de la carpeta de origen:

```sh
uv run --no-project --with "markitdown[all]" -- python "convertir_a_boveda.py" --origen "RUTA-ORIGEN" --destino "RUTA-BOVEDA/Materiales/Curso" --etiqueta "material/curso" --simular
```

Si ya tienes MarkItDown instalado en el Python activo, puedes sustituir `uv run ... -- python` por `python convertir_a_boveda.py` o el comando Python que utilices en tu sistema.

La simulación lista lo que el script haría y muestra un resumen en la terminal. **No escribe archivos ni genera el CSV.** Lee el resumen y confirma que el origen y el destino son los esperados. Si la ruta del destino quedó dentro del origen, el script se detiene con código de salida `2` y el aviso correspondiente.

## Convierte los documentos

Cuando el resumen de simulación tenga sentido, repite el comando sin `--simular`:

```sh
uv run --no-project --with "markitdown[all]" -- python "convertir_a_boveda.py" --origen "RUTA-ORIGEN" --destino "RUTA-BOVEDA/Materiales/Curso" --etiqueta "material/curso"
```

El script recorre archivos regulares que no estén dentro de carpetas ocultas. Solo intenta procesar `.pdf`, `.docx`, `.pptx`, `.xlsx`, `.xls`, `.csv`, `.html`, `.htm`, `.epub`, `.json`, `.xml` y `.txt`. Las demás extensiones se anotan como `ignorado`. El script usa `convert_local` y desactiva plugins: no convierte URLs ni activa OCR de terceros.

Por cada conversión con texto, crea una nota `.md` con propiedades `fuente`, `convertido`, `herramienta`, `tags` y `revisado: false`. También crea `_informe-conversion.csv` en el destino. No sobrescribe una nota Markdown existente; cuando un nombre ya existe, anota `omitido` con detalle `ya existe`. No uses `--sobrescribir` hasta haber respaldado el destino y entendido que reemplazará una conversión anterior.

El CSV se vuelve a generar en cada ejecución real y refleja esa corrida; si quieres conservar el historial, copia o renombra el informe anterior antes de volver a ejecutar.

Los estados del resumen y del CSV son:

- `convertido`: encontró texto y preparó una nota Markdown; en simulación solo indica lo que convertiría.
- `omitido`: ya existía la ruta de salida y no se reemplazó.
- `vacio`: MarkItDown no encontró texto para guardar. Un PDF escaneado es una posible causa; revisa el documento y no asumas que toda salida vacía es un escaneo.
- `error`: ocurrió una excepción al procesar ese archivo o la salida no pudo mantenerse bajo el destino.
- `ignorado`: la extensión no está en la lista permitida.

Un lote puede tardar; comienza con una carpeta pequeña. Si ves `vacio`, la conversión estándar no recuperó texto. MarkItDown ofrece `markitdown-ocr` como plugin que usa un cliente de modelo para leer imágenes: sus instrucciones actuales envían imágenes al modelo configurado. Antes de esa alternativa revisa el aviso de privacidad, los permisos para el material y las reglas de tu institución. No lo describas como OCR local.

### Nombres que se transforman y colisiones

Para mantener nombres compatibles con sistemas de archivos y enlaces, el script reemplaza con guiones `\ / : * ? " < > | # ^ [ ]` en nombres y carpetas de salida. Obsidian advierte que ciertos símbolos pueden interferir con enlaces; la lista exacta de caracteres que el sistema de archivos acepta depende del sistema operativo. Este reemplazo es la regla de este script, no una afirmación de que todos esos símbolos estén prohibidos en todos los sistemas.

Dos rutas distintas podrían quedar con el mismo nombre después del saneamiento. La primera crea la nota y la segunda queda como `omitido` porque la salida ya existe. El CSV conserva el nombre de origen para que puedas encontrar el caso; renombra uno de los originales y vuelve a ejecutar el lote. No borres una salida para resolverlo sin revisar primero su contenido.

## Revisa el informe y abre el destino en Obsidian

Abre `_informe-conversion.csv` en una hoja de cálculo o editor de texto. Revisa especialmente `vacio`, `error`, `ignorado` y `omitido`; también verifica que todas las rutas de salida correspondan al curso correcto. Si necesitas corregir el contenido, edita la nota convertida y conserva el original sin cambios.

Abre la bóveda en Obsidian o cambia a ella si ya estaba abierta. Las notas nuevas viven en `Materiales/<Curso>/`; abre una y comprueba las propiedades. Si no ves la carpeta todavía, confirma primero en el explorador de archivos que el script la creó dentro de la bóveda y vuelve a abrir Obsidian o la bóveda.

## Crea un índice del curso

En la raíz de `Materiales/<Curso>/`, crea una nota índice, por ejemplo `Índice del curso.md`. Enlaza cada lectura o sesión con wikilinks como `[[Semana 1 (pdf)]]`; el nombre entre corchetes debe coincidir con la nota creada. Evita leer la bóveda completa con un agente: un índice del curso ayuda a elegir solo los materiales necesarios.

Si pides a Claude Code o Codex que prepare el índice, solicita primero una propuesta de archivos y cambios. No le pidas que modifique las notas convertidas.

Puedes añadir esta regla a las instrucciones del agente (`CLAUDE.md` o `AGENTS.md`):

> `Materiales/` es una fuente de solo lectura: nunca la edites. Cuando uses información de un material, cita la nota con un wikilink. Separa lo que dice el material de lo que son mis notas. Si un archivo convertido está vacío o parece dañado, avísame.

## Estudia usando las notas

Usa el índice para seleccionar el material relevante y pide citas a las notas fuente. Por ejemplo:

- “Resume `[[Semana 1 (pdf)]]` en cinco ideas. Cita la nota en cada idea y no inventes información que no esté en el material.”
- “Haz preguntas de repaso basadas en `[[Sesión 2 (pptx)]]`. Pon la respuesta después de cada pregunta y cita la fuente.”
- “Crea un glosario con términos de `[[Lectura 3 (docx)]]`. Marca como ‘no definido en el material’ cualquier término cuya definición no encuentres.”
- “Compara `[[Semana 1 (pdf)]]` con `[[Semana 2 (pptx)]]`. Señala posibles contradicciones y cita las dos notas; si no hay evidencia suficiente, dilo.”

Compara cada respuesta con el archivo convertido y el original cuando el formato o una tabla importante se haya desordenado.

## Mantén el curso al día

Para añadir documentos, guarda los nuevos originales en la carpeta de origen y vuelve a correr el script con el mismo destino. Al no sobrescribir por defecto, las notas que ya existen se omiten y los nuevos archivos se agregan. Mira el informe de cada ejecución.

En Obsidian, busca `revisado: false` para repasar las conversiones pendientes. Después de comparar una nota con su original y confirmar que es utilizable, cambia su propiedad a `revisado: true`. No marques como revisado un documento vacío o con tablas dañadas.

## ¿Cómo sé que funcionó?

- La simulación mostró un resumen y no creó archivos ni CSV.
- La ejecución real creó las notas y `_informe-conversion.csv` únicamente dentro de `Materiales/<Curso>/`.
- Cada nota tiene las propiedades `fuente`, `convertido`, `herramienta`, `tags` y `revisado: false`.
- Una segunda ejecución marca como `omitido` lo que ya existe y deja intacta la nota anterior.
- Los archivos originales siguen en la carpeta de origen.
- Obsidian muestra la carpeta y puedes abrir sus notas.
