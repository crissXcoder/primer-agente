Esta guía te ayuda a entender las conexiones MCP para QGIS y a escoger un proyecto según tu agente, versión de QGIS y nivel de confianza. No instala nada ni garantiza que una combinación concreta funcione en tu computadora. La guía genérica de MCP para el agente todavía no está disponible; por eso aquí explicamos lo necesario para comparar, sin enlazar una página pendiente.

Si es tu primera vez con QGIS, empezá por [instalar y preparar QGIS](/guias/qgis-instalar-y-preparar). Para aprender a revisar complementos, consultá [instalar y gestionar plugins](/guias/qgis-plugins-instalar-y-gestionar).

## Qué significa conectar QGIS con MCP

MCP es un protocolo para que una aplicación cliente de IA use herramientas que ofrece otro programa. El cliente puede ser un editor o agente de código; el modelo que usa ese cliente puede ser local o remoto. El servidor MCP traduce las solicitudes a operaciones del complemento dentro de QGIS. La palabra “local” describe dónde corre esa conexión, no necesariamente dónde se procesa el texto que enviás al modelo.

```text
Persona
  │ pide una tarea
  ▼
Agente / cliente MCP ── stdio ──► Servidor MCP local
                                      │
                                      │ socket TCP local (127.0.0.1)
                                      ▼
                                Plugin de QGIS
                                      │ API PyQGIS
                                      ▼
                                    QGIS
```

Esta arquitectura es la que varios proyectos describen. No todos comparten los mismos formatos, puertos, controles ni funciones; algunos pueden omitir una pieza o combinar servidor y plugin. Confirmá el README y la versión de cada componente antes de conectar.

## Qué puede hacer y qué no hace MCP

Un servidor puede exponer operaciones como consultar capas, filtrar elementos, ejecutar algoritmos de Processing, cambiar estilos, exportar archivos o editar entidades. Cada acción disponible depende del proyecto y del plugin. MCP no es un modelo, no valida por sí solo que el análisis geográfico sea correcto y no decide si tenés autorización para modificar un conjunto de datos.

Revisá los parámetros y resultados antes de guardar cambios. Para practicar, usá una copia del proyecto y datos de ejemplo. Pedile al agente que explique qué capa, archivo y operación va a tocar; no aceptés una orden vaga como “arreglá el mapa” si puede modificar datos.

## Cómo elegir

Seguí estas preguntas en orden:

1. **¿Qué cliente MCP usás?** Revisá primero la documentación oficial de ese cliente y confirma que admita servidores locales por `stdio`. Codex, Claude Code, Cursor y otros clientes pueden guardar la configuración en lugares diferentes. Un README que menciona un cliente no certifica todos sus sistemas operativos.
2. **¿Qué versión de QGIS tenés?** Compará la versión instalada con el rango del plugin y el servidor. Si usás QGIS 3.28 o una versión anterior, no elijás una opción que declare únicamente QGIS 3.44+. Si vas a actualizar QGIS para este uso, primero comprueba que tus otros plugins y proyectos sean compatibles.
3. **¿Querés usar un modelo local?** MCP conecta cliente y herramientas, pero no obliga a usar un proveedor concreto. Verificá en la documentación vigente del cliente cómo enruta solicitudes a un modelo local y qué datos siguen saliendo del equipo. La conexión local a QGIS no garantiza procesamiento local del modelo.
4. **¿Es para un taller de principiantes?** Preferí una opción cuya ficha explique claramente cliente, versiones, instalación del plugin, instalación/configuración del servidor y cómo desconectarla. En una actividad grupal, usá un proyecto de práctica sin datos personales, hacé la conexión en una máquina de prueba y fijá una misma combinación de versiones para el grupo.
5. **¿El servidor y el plugin se distribuyen por separado?** Anotá sus versiones y cómo fijarlas. Evitá copiar sin cambios comandos que descarguen `main` o `latest`: el contenido remoto puede cambiar y dejar componentes incompatibles. Preferí un release versionado o un commit específico y conserva esa referencia para repetir la configuración.

Para empezar a comparar, el proyecto `nkarasiak/qgis-mcp` declara una gama amplia de clientes y documenta tanto el servidor como su plugin. No lo recomendamos automáticamente: si la versión de QGIS no coincide, si querés otro modelo/cliente o si no podés fijar componentes, la mejor opción puede ser esperar o practicar sin conexión MCP. El proyecto `jkoets` requiere especial cautela en un taller porque declara ejecución de código PyQGIS arbitrario.

## Riesgos y controles para empezar

<Callout type="peligro">
Aunque el servidor y QGIS corran en tu computadora, las instrucciones y resultados que mandás al agente pueden enviarse al proveedor del modelo. Capas, nombres de archivo, atributos, consultas, capturas y rutas pueden contener información sensible. Revisa las reglas de privacidad del cliente y proveedor; para probar, usa datos públicos o ficticios.
</Callout>

- **Código y edición de datos:** si una herramienta puede ejecutar código o editar capas, tratá cada llamada como una acción con impacto. Usá copias, revisá el plan, confirmá antes de escribir/exportar y guardá una copia de respaldo.
- **Socket local sin autenticación:** `127.0.0.1` limita la escucha a la máquina según la configuración declarada, pero cualquier proceso local con acceso suficiente podría intentar conectarse. No expongás el puerto a la red ni uses túneles/reenviadores; detené el plugin cuando terminés. Un token opcional es una capa adicional, no una caja de aislamiento.
- **Versiones que cambian:** evitá `main`, `master` o etiquetas flotantes como referencia de instalación permanente. Elegí release/commit, anotá versión del plugin y del servidor, y actualizá ambos de forma coordinada.
- **Instrucciones dentro de datos:** un nombre de capa, atributo o archivo podría contener texto como “ignora instrucciones anteriores”. Tratá esos datos como contenido, no como órdenes. El agente debe seguir tus instrucciones y no ejecutar texto encontrado en los datos como código.
- **Privilegios y daños:** corré el agente con una cuenta normal, sin permisos administrativos innecesarios. Quitá herramientas que no ocupés si el proyecto permite limitar capacidades, y no conectés carpetas completas si basta un proyecto de muestra.
- **Cadena de suministro:** revisá el autor, el repositorio de origen, release, licencia, dependencias y avisos antes de instalar. El repositorio oficial de plugins ayuda a descubrir y distribuir complementos, pero no reemplaza la revisión de confianza y compatibilidad.

La documentación de seguridad de MCP también recomienda tratar con cuidado el acceso a herramientas, consentimiento y datos. La interfaz de aprobación del cliente ayuda a revisar acciones, pero no vuelve confiable a un servidor desconocido.

## Cómo identificar el plugin correcto

1. Abrí el README del servidor que decidiste evaluar y copiá el nombre exacto del plugin, repositorio y release.
2. En QGIS, abrí **Complementos → Administrar e instalar complementos** y buscá ese nombre exacto. Revisá autor, versión, compatibilidad y enlace al código fuente.
3. Si el README indica instalar desde ZIP o desde un repositorio adicional, confirmá que el enlace lleve al proyecto elegido y no a un fork con nombre parecido. No habilités repositorios experimentales solo para probar al azar.
4. Compará las instrucciones de arranque, puerto y versión del servidor MCP con las del plugin. Un resultado `ping` exitoso confirma comunicación básica cuando el plugin está ejecutándose; no valida cambios, análisis ni exportaciones.
5. Si no lográs determinar que ambos componentes pertenecen al mismo proyecto y release, detenete y no conectés tus datos.

## ¿Cómo sé que funcionó?

La guía cumplió su propósito cuando podés explicar qué papel cumplen el cliente, servidor, socket y plugin; encontrás el rango de QGIS declarado por el proyecto que estás evaluando; y podés señalar al menos un riesgo y su control antes de instalar.

Esta guía no proporciona una salida de terminal esperada porque no instala ni ejecuta un servidor. Para confirmar una instalación real, seguí la prueba `ping` que documente el proyecto elegido, con QGIS abierto y el plugin iniciado. Si QGIS está cerrado, que falle la conexión solo indica que el puente no está disponible; no demuestra que la instalación esté mal.
